# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Online exam site (Vietnamese UI, ~100–300 simultaneous students) for a diocese catechism exam. SvelteKit 3 + `@sveltejs/adapter-cloudflare` 8 on **Cloudflare Workers**, **D1** (binding `DB`) as the source of truth, **Google Sheets** only as a copy for teachers to grade essays. Sheets must never be read or written while students are taking the exam (only after submit, via `waitUntil`, and in the admin import/resync). `README.md` (Vietnamese) holds the Sheet tab layouts, the full deployment guide for Workers & Pages, and the design decisions; don't duplicate it here.

## Commands

```bash
npm run dev                  # vite dev; D1 local in .wrangler/state (secrets from .dev.vars)
npm test                     # vitest, once. Watch mode: npm run test:unit
npx vitest --run src/lib/server/thi.test.ts -t "part of test name"   # single test
npm run check                # wrangler types + svelte-kit sync + svelte-check (must be 0 errors)
npm run build && npm run preview   # production build on real workerd (port 4173)
npm run db:migrate           # apply migrations/ to local D1 (tables are empty afterwards)
npm run db:mau               # load SAMPLE data locally (src/lib/server/testing/mau.sql)
npm run db:hoc-vien          # load real roster from resources/ds_hoc_vien.csv (add :remote for production)
.venv/bin/python scripts/tao-sheet-de-thi.py   # resources/*.csv -> resources/de-thi-2026.xlsx (needs openpyxl)
```

`worker-configuration.d.ts` is generated by `wrangler types` and git-ignored; `prepare`, `build` and `check` regenerate it (run `npm run gen` after editing `wrangler.jsonc`).

## Architecture

All business logic lives in `src/lib/server/`; route files under `src/routes/api/*/+server.ts` are thin adapters that pass `env.DB` and the request in.

- **`thi.ts`** – the exam flow against D1: `timHocVien` (live search) → `batDau` (creates the attempt) → `luuBai` (autosave) → `nopBai` (submit) → `ketQua`; plus `trangThaiThi` (payload for `/thi`) and `thongTinTrangChao`.
- **`exam.ts`** – pure functions: `taoDe` (builds a student's paper), `chamTN` (scoring), `thoiGian` (time rules).
- **`admin.ts`** – import from Google Sheet tabs `CauHoi`, `PhanThi`, `HocVien`, `ThongTin` into D1; `chayAdmin` wraps admin endpoints (token check + errors as JSON). **`sheets.ts`** – Sheets REST client (service-account JWT signed with Web Crypto, no `googleapis`), result row layout (columns A..M), `dongBoMot` (after submit) and `dongBoLai` (resync). **`hoc-vien.ts`** – roster parsing/CSV/SQL.
- **`normalize.ts`** – `chuanHoa` strips Vietnamese diacritics (incl. đ) for search keys; originals are always stored with diacritics.

Key design rules that span several files:

- **Identity is roster-based**: students pick their own row from `hoc_vien_cho_phep` (live search); `luot_thi.hoc_vien_id` is `UNIQUE`, which is what prevents a second attempt. No free-form identity fields. Roster rows are upserted by `khoa` (normalized name + holy name + duplicate counter) so re-importing keeps ids of people who already took the exam.
- **The server owns time**: `started_at` is written at start; the T/2 minimum before submit, late flag (`nop_tre`) and tolerance are all computed server-side. Never trust client time.
- **Answer keys never leave the server**: `cau_hoi.dap_an` is only read in `chamTN`/tests. Each student's paper is stored in `luot_thi.de_thi` as `[{ma, thu_tu?}]` (shuffled option order per student); client answers are indices into the *displayed* order.
- **Sessions**: random token in an httpOnly cookie, only its SHA-256 is stored (`token_hash`). `token_hash = NULL` means "supervisor unlocked this attempt for another device" (see README).
- **Submit is idempotent** via state-conditional SQL (`WHERE trang_thai = 'dang_thi'`) inside one D1 `batch`; creating an attempt is a batch too.
- **Exam structure is data, not code**: `cau_hinh_nhom` = ordered sections (title, instructions, count, `xao_tron`). Question types: `TN` (auto-graded), `DK` (short fill-in) and `TL` (long essay), the last two graded by teachers in the Sheet. Sections are never mixed; the last section has `xao_tron = 0` (fixed order, bank order = `ORDER BY rowid`). Welcome-page text and exam duration come from the `ThongTin` tab.

## Gotchas

- SvelteKit 3 has no `$lib` and no `event.platform`: import `#lib/...` **with the `.ts` extension** in routes, and get bindings via `import { env, waitUntil } from 'cloudflare:workers'`. `hoc-vien.ts` imports `./normalize.ts` with extension because Node runs it directly in `scripts/hoc-vien-sql.mjs`.
- **CSRF**: in production SvelteKit rejects any POST without `Content-Type: application/json` (or with a form type) with 403 `Cross-site POST form submissions are forbidden`. The check does not run in `vite dev`, so test API calls against `npm run preview`. Always send JSON (`-d '{}'`).
- **Migrations**: never edit an applied migration; add a new numbered file. Sample data must not go in `migrations/` (it reaches production); it lives in `src/lib/server/testing/mau.sql`, which `testing/d1.ts` (a `node:sqlite` stand-in for D1 used by the tests) also applies after the migrations. Tests rely on its roster ids 1–5 and its 30-minute config.
- Sheets tests stub global `fetch` and sign with a real generated RSA key; they must not hit Google.
- Worker name in `wrangler.jsonc` (`glhn-exam`) must equal the Worker name in the Cloudflare dashboard or Workers Builds fails. `preview_urls`/branch builds share the production D1.
- `.dev.vars` may hold **real** service-account credentials: running the admin import locally reads (and may write the header row of) the real Google Sheet. Don't print or commit it.
- `resources/` holds the real answer key and student names and is untracked; `ds_hoc_vien.csv` is git-ignored. Never `git add -A` blindly — stage files explicitly.
- UI is Tailwind v4 + a custom daisyUI theme `fluent` in `src/routes/layout.css` (Fluent 2 sizes, Merriweather font, logo-derived brand colors). Overrides of daisyUI components sit **outside** `@layer` so they beat daisyUI's layered rules. Keep daisyUI default component sizes (no `btn-sm` etc.).
- Conventions: identifiers and UI text are Vietnamese (`batDau`, `luot_thi`); comments marked `ponytail:` are deliberate simplifications; **commit messages are written in English**.
